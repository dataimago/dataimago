There needs to be an engine that largely helps enacts the mission, vision and philosophy of dataimago. That engine, we believe, lies in the use of data and they aims associated with its use. At the heart of the endeavor is data.

We, as data scientists, believe that the current state of AI is not as such that one can throw large sets of data at even the most advanced AI systems and say, "make sense of it" and anything of much use will come out. This is particularly true in fields, like education, where high quality data has existed for more than a half a century and many highly advanced techniques have been developed in an attempt to derive useful information. A data scientist as content area currator is necessary to find the "good" ways to utilize the data, highly likely with AI assistance. 

To advance the mission, vision and philosophy of dataimago we envision an architecture built around the use of the R statistical software environment specifically associated with the construction of R packages to perform highly specialized data analytics. We couple this with Quarto documentation and a website building (qmd to html conversion made simple) for the publication of documentation about both the package itself as well as what it can do (rendered in documents, presentations, blogs, scrolly-telling demos, ...). With all of this hosted on a GitHub web repository, A cornerstone of the application framework we envision for quickly prototyping and creating highly specialized and highly scalable data science packages, that instantiate dataimago's foundational principles. 

In our current development, we have put in place R/Quarto/GitHub projects. The results are not finalized, but there has been ample progress to begin mapping out project requirements for the next phase: Integrates into a NextJS application for hosting on, say, Vercel.

Below is a directory structure associated with such an application considered with AI assistance. 

The goal of NextJS integration is to, in a sense, create a web-application for the R package(s) existing in R/Quarto/GitHub. This web-application at a bare-minimum is a high-quality documentation site associated with a projects and its R packages. But being based upon a full fledged application framework like NextJS opens up numerous other possibilities for interacting with R packages and the results that they produce:

1. Much richer content (html based reports, blogs, scrolly-telling, and presentations) can be showcased and exported to end users, perhaps in a personalized fashion.
2. Potential integration with AI to allow users to interact with the analytics and associated output from the R packages. Asking questions of the data that the AI can assist in answering. Integration with AI would involve utilizing Model Context Protocol to expose aspects of the R packages to AI control as tools and resources. With those tools an resources advanced AI can rapidly assist in the creation of highly customized content that can be prototyped and delivered to end users.
